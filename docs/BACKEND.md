# Бэкенд: что происходит при ревью ТЗ

Отдельного бэкенд-сервиса нет: это Next.js, три API-роута. Основной путь — `POST /api/review`.

Базы, очереди, Confluence, MCP нет. Ключ Groq читается из `.env.local`. Без ключа ревью всё равно работает — только эвристики, без модели.

## Что вызывается с экрана

| Запрос | Зачем |
| --- | --- |
| `POST /api/review` | разобрать ТЗ и вернуть замечания |
| `POST /api/export` | собрать Word/PDF из уже готового отчёта |
| `GET /api/samples?id=…` | отдать текст примера |

Правила по умолчанию отдаёт `GET /api/rules`. В прогоне ревью фронт обычно шлёт свой список правил (в том числе после «Обновить 8 обязательных правил»).

## Прогон ТЗ, шаг за шагом

Аналитик жмёт отправку → фронт шлёт `FormData`: файл и/или текст плюс 8 правил (если их правили в UI).

### 1. Вход

PDF через `unpdf` раскладывается по координатам в markdown: заголовки, списки, таблицы. Остальное читается как текст. Потом `formatSpecText` подчищает плоскую простыню. Пустой документ → 400.

Код: `src/app/api/review/route.ts`, `src/lib/pdf-layout.ts`, `src/lib/format-doc.ts`.

### 2. Эвристики (код, без LLM)

Текст режется на разделы, блок «История изменений» выкидывается. По 8 правилам ищутся дыры:

- нет Data Catalog
- нет кластера Kafka
- «папка» вместо полного пути HDFS
- нет NULLABLE / NOT NULL
- нет фильтров или явного «не применимо»
- нет справочников
- противоречия вроде инкремент vs полная перезагрузка

Каждая находка уже в формате комментария: место, цитата, почему, вопрос, роль, HIGH / MEDIUM / LOW.

Код: `src/lib/parse.ts`, `src/lib/heuristics.ts`, `src/lib/rules.ts`.

### 3. Одна модель, три запроса подряд

Та же Qwen на Groq (`qwen/qwen3.8-27b`). Thinking выключен (`reasoning_effort: none`), чтобы три вызова влезли в бесплатный лимит.

1. **Шаблон** — пустые разделы, Catalog, «не применимо» (правила 2 и 5).
2. **Разработчик** — Kafka, сериализация, HDFS, NULLABLE, зерно (правила 1, 3, 6, 7).
3. **QA** — фильтры, справочники, краевые случаи, SLA (правила 4 и 8).

Каждому уходит не весь PDF целиком, а оглавление + урезанные разделы под его линзу, список уже найденного и чеклист. Ответ — JSON. Между ролями пауза ~2.5 с; при 429 — повтор. Если ключа нет или роль не ответила, эвристики не пропадают.

Код: `src/lib/llm.ts`.

### 4. Склейка

Дубли режутся. Пустое «уточните требования» без якоря выкидывается. Текст ТЗ модель не переписывает. Сортировка по тяжести → вердикт `not_ready` / `needs_work` / `ready`.

Код: `src/lib/llm.ts` (`mergeFindings`, `finalizeReview`), вход в конвейер — `src/lib/review.ts`.

### 5. Ответ фронту

JSON: `findings`, `summary`, `counts`, `llmCalls`, `rolesRan`, плюс нормализованный `text` для подсветки в предпросмотре.

```
PDF или текст
    → разбор в markdown
    → эвристики: 8 правил
    → Qwen: шаблон
    → Qwen: разработчик
    → Qwen: QA
    → склейка и вердикт
    → JSON замечаний
```

## Выгрузка

`POST /api/export` модель не вызывает. Фронт уже собрал отчёт (комментарии + текущий текст ТЗ, в том числе правки из предпросмотра). Сервер рисует `.docx` (`docx`) или `.pdf` (`pdfkit` + Noto Sans для кириллицы) и отдаёт файл.

Код: `src/app/api/export/route.ts`, `src/lib/export-files.ts`, `src/lib/export-report.ts`.

## Что сознательно не делается

- модель не исправляет абзацы ТЗ
- нет агент-платформы, MCP, Confluence
- нет своей обученной модели
- связанные документы сами не подтягиваются
- поля «истории изменений» страницы не ревьюятся

Итого: бэкенд — конвейер «разобрать → чеклист кодом → три роли одной LLM → склеить». Модель только указывает места. Решение «готово в разработку» считается по high/medium; аналитик его не обязан принимать.
