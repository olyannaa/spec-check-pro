# Витрина-агрегат устройств абонентов

Источник: встроенный полный тестовый набор. Обезличено.
Документ специально дырявый: все 8 правил, противоречия и ошибки полей.

## Общие сведения

Витрина CDM считает активные устройства по регионам и вендорам.
Агрегат строится из потока IUM и выгружается в TABLE_AGG_DEVICES.

## Решаемая проблема

Отчёты по устройствам собирают вручную, единой витрины нет.

## Продуктовые метрики

- Задержка: < 1 мин
- Пропускная способность: до 100 000 событий/сек
- Стриминг в реальном времени (задержка ≈ 0 сек)

## Нефункциональные требования

- Инкрементная загрузка
- Хранение: Kafka — 24 ч, RAW — 30 дней, HDFS — «как договоримся»
- Объём: 100 000 соб/сек без разбивки по региону и слою

## Системы-источники

IUM — IN-платформа (сбор событий интернет-трафика, звонков и SMS).

## Схема потоков данных

IUM → Kafka (топики по регионам) → Apache Flink → RAW → CDM

- Мониторинг: LINK_DASHBOARD_DEVICES
- Исходный код: LINK_GITLAB_PROJECT
- JIRA: LINK_JIRA_TASK

## Алгоритм расчёта

### Шаг 1. Выбор пользователей

Берутся все FIELD_IMSI из RAW за месяц.
Фильтр: события не старше текущего времени плюс 2 часа вперёд и 7 дней назад.

### Шаг 2. Определение вендора

Для каждого IMSI берётся последний IMEI.
tac = substring(imei, 1, 8). Дальше FIELD_VENDOR_NAME из TABLE_DEVICE_REF.

### Шаг 3. Преобразования на потоке

Из этих полей удаляются лидирующие нули. Список атрибутов не приведён.

### Шаг 4. Агрегация

Группировка по FIELD_REGION_NAME, FIELD_VENDOR_NAME, FIELD_USERS_CNT = count(distinct FIELD_IMSI).
