# Обязательные проверки (от кейсодателя)

Источник: `Основные моменты документации.pdf`.
В исходном PDF у пунктов обрезана первая буква; формулировки восстановлены по смыслу.

Это жёсткий чеклист агента. Пропуск любого пункта хуже лишней придирки.

| # | Правило | Что искать в ТЗ | Что писать аналитику, если нет |
| --- | --- | --- | --- |
| 1 | **Спецификация сериализации** | Модель входного и выходного потока: формат, схема, тип сериализации/десериализации | Где Avro/JSON/CSV/ORC? Схема совместима с источником и приёмником? |
| 2 | **Привязка к источникам** | Прямая ссылка на Data Catalog, не «см. систему X» | Добавить ссылку на каталог для каждого источника |
| 3 | **Описание витрин** | Для **каждого** поля признак обязательности NOT NULL / NULLABLE | Какое поле может быть пустым, какое нет |
| 4 | **Типовые фильтры** | Стандартные условия фильтрации при построении витрины и выгрузке | Что отсекаем на входе? Если ничего — явно «не применимо» |
| 5 | **Структура шаблона** | Все разделы шаблона на месте. Нет этапа → формулировка «не применимо» | Не удалять раздел и не оставлять пустым |
| 6 | **Инфраструктурные параметры** | Кластер Kafka для потоковых источников и приёмников | Имя кластера, не только топик |
| 7 | **Хранение данных** | Для файловых хранилищ полный путь HDFS и формат | Не «папка», а полный путь + ORC/CSV/parquet |
| 8 | **Нормативно-справочная информация** | В витрине перечень используемых справочников | Какие справочники, ключ джойна, что если нет записи |

## Как это стыкуется с тестовыми данными

В `Тестовые данные для Хакатона.pdf` отдельно выделены 4 фокуса. Они не вместо чеклиста, а поверх него:

1. Расположение источников и Kafka-кластеров → правила 2, 6, 7
2. Поля и логика расчёта → правило 3 + маппинг и алгоритм шаблона
3. Фильтрация → правило 4
4. Обновление и объём данных → нефункциональные требования шаблона + ключ/партиция

Тест кейсодателя: **новый** документ витрины-агрегата. Витринные правила (3, 4, 8) не ослаблять.
