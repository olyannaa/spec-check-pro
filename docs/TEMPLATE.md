# Шаблон документации NET

Источник: `Шаблоны документации.pdf`. Один шаблон на **потоковые данные и витрины**.

Поля **«История изменений»** в ревью не используем — по договорённости с кейсодателем они невалидны для этой задачи.

Если раздела нет в документе, это находка. Если этап обработки не нужен, в ТЗ должно быть явно **«не применимо»**, а не пусто.

## Структура

### Шапка документа

| Раздел | Что должен заполнить аналитик |
| --- | --- |
| Общие сведения | Краткое описание потока / витрины |
| Решаемая проблема | Зачем создаётся, какие задачи закрывает |
| Продуктовые метрики | Какие метрики изменятся |
| Заказчики | Продукт или подразделение |
| Нефункциональные требования | Как минимум объём данных и задержки |
| Системы-источники | Перечень и краткое описание |
| Data Catalog | Прямая ссылка |
| Исходники проекта | Ссылка на GitLab |
| Команда | Аналитик и разработчик |
| JIRA | Задача |
