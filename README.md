# SPEC CHECK PRO

SPEC CHECK PRO — интерфейс для проверки ТЗ: ввод документа, цветные маркеры и рельс комментариев.

Аналитик вставляет текст или PDF. Решение проверяет ТЗ по **правилам** (восемь обязательных плюс свои) и ставит замечания **HIGH / MEDIUM / LOW**. Текст сам не переписывает.

Одна LLM, **три последовательных запроса** с разными ролями:

1. **Аналитик** — пустые разделы, Data Catalog, «не применимо», пользовательские правила
2. **Разработчик** — Kafka-кластер, сериализация, HDFS, NULLABLE, зерно
3. **Тестировщик** — фильтры, справочники, краевые случаи, SLA

Эвристики по правилам всегда идут первыми; модель добавляет находки, не заменяет чеклист.

Модель: **Qwen 3.8 на Groq**, бесплатный тариф. Без ключа работают шаблон и эвристики.

PDF разбирается по координатам на странице: заголовки, списки и таблицы остаются таблицами, а не одной простынёй текста.

## Запуск

```bash
npm install
npm run dev
```

http://127.0.0.1:43142

Ключ Groq (карта не нужна): [console.groq.com/keys](https://console.groq.com/keys)

```bash
# .env.local
GROQ_API_KEY=gsk_...
OPENAI_BASE_URL=https://api.groq.com/openai/v1
OPENAI_MODEL=qwen/qwen3.8-27b
```

Внутренний контур компании — те же переменные, другой `OPENAI_BASE_URL`.

## Экран

- Слева: большое поле ввода, «Прикрепить файл», **«Правила проверки»** (добавить / изменить / удалить), красная кнопка отправки.
- **«Проверить тестовый шаблон»** — короткое демо-ТЗ. **«Проверить полный набор случаев»** — все 8 правил, таблицы, противоречия и ошибки полей. Файл не нужен. Тексты: [docs/samples/00-test-template.md](docs/samples/00-test-template.md), [docs/samples/00-test-template-full.md](docs/samples/00-test-template-full.md).
- После проверки: предпросмотр документа с подсветкой и комментарии справа. У каждого комментария — роль (Шаблон / Разработчик / QA).
- **Word** и **PDF** скачивают текущий текст ТЗ (с правками из предпросмотра) в том же виде, что исходный документ и шаблон: заголовки, списки, таблицы. Без шапки ревью и без карточек замечаний.
